# 场景2汽车旅馆 UI：Codex 实施指令

请直接在当前 Unity 项目里实现这一版已确认的场景2 UI。项目已有场景1 UI，请先读取项目 AGENTS.md、Unity 版本和现有场景/Prefab/脚本/资源组织，复用实际实现，并完成编辑、保存与实际显示检查。

## 参考与优先级

- `Design/Scene2Motel/scene2_ui_reference.png`：用户确认的场景2内容与配色效果图。
- `Design/Scene2Motel/scene1_ui_layout_reference.png`：当前场景1的布局截图。
- `Assets/ThatGameJam2026/Scene2Motel/Art/`：用户提供的17张原始PNG，原样保留。
- `Design/Scene2Motel/palette.json`：近似配色目标。
- `Design/Scene2Motel/sprite_bounds.json`：原图透明有效区域、Unity Sprite Rect和素材用途。

当生成效果图与当前项目的UI几何位置存在细微差异时，以项目当前场景1的几何布局为准。场景2效果图决定新插画、新道具、配色和风格，不要求照抄生成图的偶然比例偏差。

## 实施范围

1. 找到并复用现有场景1 UI。根据项目实际结构，新建场景2场景、Prefab副本/Variant，或新增主题配置；优先采用项目已有的场景与数据切换方式。不要全局改色而影响场景1。当前任务的结果必须能在Unity里打开并运行。
2. 保留全部UI元素的位置、尺寸、锚点、轴心、间距、圆角、层级、纸张轮廓、纹理、阴影与叠放角度：顶部导航、左侧物品栏、选中框、底部空白纸卡、中央网格底纸及衬纸、右侧横线本、顶部纸签、上方圆角对话块、横向长条和书签。
3. 中央插画改用 `Art/Room/room_lights_on.png`。等比适配中央原有插画区域，保留完整房间构图、手绘轮廓、透明边缘和四周网格纸留白。不要拉伸、重画房间、加滤镜或保留音乐厅画面。关灯图为备用资源，不新增切换按钮。
4. 左侧仍是两列三行的六个位置，必须与确认稿一致：

| 位置 | 素材 |
| --- | --- |
| 左上 | `Art/Props/violin_case.png` |
| 右上 | `Art/Props/beer.png`，两瓶与小罐保持一组 |
| 左中 | `Art/Props/coat.png` |
| 右中 | `Art/Props/open_suitcase.png`，确认稿中的选中状态 |
| 左下 | `Art/Props/music_score.png` |
| 右下 | `Art/Props/biscuit_tin.png` |

5. 保留原有选中框形状和实际选择交互；初始预览状态可选中右中行李箱。不得给每个道具添加原本没有的格子、底板、文字或装饰。
6. 原图含大量透明留白。背包图标应按 `sprite_bounds.json` 中有效范围建立或配置Sprite，再等比适配现有槽位；原始PNG保留。不要直接缩整张大画布导致道具过小，也不要仅切换Tight网格就假设Sprite Rect已裁掉留白。中央房间与原场景的热点如果采用源图像素坐标，需同步按实际Sprite Rect换算。
7. 按确认稿调整UI配色：暖深橄榄棕背景、灰鼠尾草绿物品栏与衬纸、深橄榄网格底纸、杏桃强调纸条、旧米白纸张、灰绿圆角对话块、赭黄纸签与选中框。配色值见palette.json。
8. 保留纸张真实纹理、褶皱、纤维和明暗。检查原贴图是否自带染色：普通Image颜色通常是乘色，不能把深蓝贴图直接准确改成浅杏桃。优先复用中性/灰度纸纹并设定颜色；必要时为场景2使用独立的纹理着色材质或独立换色资源，保持轮廓、透明度和纹理。不得用普通纯色方块替代纸张，也不得直接改动场景1共享材质的颜色。场景插画和道具保持原图色彩，防止继承旧Image Tint。
9. 继续使用项目现有UI技术栈与Canvas缩放方案。保留PC界面的小字号比例，不增大字体。不新增剧情文案；效果图里的空白纸签继续留白，现有剧情数据绑定继续保留。不要新建与本任务无关的框架。
10. 界面应继续由独立可编辑、可交互的组件组成。整张确认效果图只用于对照，不得作为单张背景覆盖运行界面。

## 交互与完成检查

- 检查并复用项目现有物品选择、场景热点和对话接口。将旧音乐厅热点移除/停用，在项目已有场景2数据存在时接入对应房间热点；不得把旧场景1事件错误绑定到新道具。
- 不凭空编造谜题或剧情行为；缺少场景2剧情数据时，完成画面、道具选择和现有通用交互，明确报告尚需提供的剧情绑定。
- 如果Unity MCP可用，使用它读取场景、设置对象并核对Game视图；不可用时可用项目适配的Editor脚本生成/更新真实场景或Prefab文件。不要只输出代码片段让用户手动摆放。
- 打开场景2，以项目既有参考分辨率核对，另外检查1920×1080和1280×720下是否有明显错位、拉伸或遮挡；不强制改变既有Canvas设置。
- 确认脚本编译成功，点击六个道具时选中框正常，不被无交互的装饰Image挡住点击。确保场景1仍正常。
- 如果有Game视图截图能力，输出实际效果截图与确认稿比较，再进行必要的视觉调整；没有运行能力时如实说明哪些检查未运行，不声称验证通过。
- 完成后简要列出场景2入口、修改的场景/Prefab/脚本/材质位置，以及实际运行验证结果。先完成授权范围内的实施，不要只给方案。
